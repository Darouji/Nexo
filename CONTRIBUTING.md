# Contribuir

Antes de cambiar un módulo, describe el caso de uso y su impacto en permisos, datos y trazabilidad. Usa datos ficticios y una base local nueva. No publiques datos de clientes ni secretos.

Mantén el alcance de cada cambio acotado. Ejecuta las comprobaciones del README para los módulos afectados y documenta cualquier limitación. En cambios de inventario, compras o ventas, verifica también los efectos sobre Kardex, auditoría y transacciones.

La disponibilidad del código para evaluación profesional no equivale a una licencia de reutilización. Consulta al autor antes de redistribuir o usar el proyecto fuera de su evaluación.
